## 2024-05-18 - Supabase Batch Inserts vs Fault Tolerance
**Learning:** Supabase Python client `.insert([...])` operations fail entirely if a single record violates a constraint or fails insertion. In an operation like `insert_full_resume` where many child records (e.g. skills or technologies) are inserted, failing the whole operation because one technology failed to save is an unacceptable regression from the previous row-by-row `try/except` approach, even if the row-by-row approach suffered from N+1 query latency.
**Action:** Always implement a hybrid fallback pattern when converting sequential Supabase inserts to batch inserts: Attempt `db.table().insert(records).execute()`. If it throws an exception, catch it, log a warning, and fall back to iterating over the records and inserting them one-by-one inside individual `try/except` blocks.
