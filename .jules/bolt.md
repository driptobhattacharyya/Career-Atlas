## 2025-01-20 - Batch Supabase Inserts to Prevent N+1 Query Latency
**Learning:** Using sequential `.insert().execute()` calls for arrays in the Supabase Python client creates significant N+1 query latency, blocking the event loop. However, replacing all sequential inserts with bulk arrays blindy causes issues when partial failures are expected without `on_conflict` semantics.
**Action:** Always accumulate child records (like skills, bullets, and technologies) into an array and perform a single `.insert([...]).execute()`. For objects that require per-row error handling (like certifications where some may fail but others succeed), retain the original `try/except` loop unless `ignore_duplicates` or `on_conflict` is explicitly supported by the data model. Ensure variables mapped from `data.get()` arrays validate `isinstance(item, dict)` before attempting `.get()` inside list comprehensions or loops.
